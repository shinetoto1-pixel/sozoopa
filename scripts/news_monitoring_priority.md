# 뉴스 모니터링 & 테마 선정 프로세스

## 0단계: 개장일 확인 (가장 먼저 체크)
평일이면서 한국 증시 공휴일이 아닌지 먼저 확인한다. 주말/공휴일이면 "장전뉴스" 포스팅 자체를 스킵한다.
(2026-07-25는 토요일이라 이 체크를 안 하고 진행했다가 허구의 시황 초안을 만든 적 있음 — 반드시 먼저 확인할 것)

## 소스
다음뉴스 (news.daum.net) — 네이버뉴스는 접속 차단되어 대체 사용
- 경제 섹션: news.daum.net/economy
- 사회 섹션: news.daum.net/society
- 정치 섹션: news.daum.net/politics
- IT/과학 섹션: news.daum.net/tech
- 국제 섹션: news.daum.net/world

각 섹션 페이지 안에 하위 카테고리별 최신 기사 목록이 함께 표시됨 (탭 이동 불필요).

## 모니터링 시간대
전일 장 마감(15:30) ~ 당일 오전 7:30 사이 발행된 기사만 대상으로 한다.
다음뉴스 기사 URL(`v.daum.net/v/YYYYMMDDHHMMSSmmm`)에 발행시각(KST)이 인코딩되어 있어 이걸로 정확히 필터링 가능.
목록에 뜨는 "N분 전/N시간 전" 상대시간은 대략적인 참고용이고, 정확한 판단은 URL 타임스탬프 기준으로 한다.

## 섹션 우선순위

### 우선순위 1 (핵심)
- 경제 > 경제정책 / 산업 / 주식 / 벤처스타트업 / 국제경제

### 우선순위 2 (보조)
- 경제 > 가상자산 / 연금노후
- 사회 > 의료보건 / 재난안전

### 참고사항 (교차 확인용, 그 자체로는 테마 아님)
- 정치 > 외교국방 / 북한
- 국제 섹션
- IT과학 > 테크 / AI / IT기업 / 우주(국지성 강해 보수적으로 판단)

## 테마 선정 방법론 (중요: 순서를 지킬 것)

1. **원문 그대로 수집**: 키워드 사전 없이, 시간창 안의 기사 제목+요약을 전부 모은다. 미리 "이런 테마가 있겠지"하고 짜맞추지 않는다.
2. **내용을 읽고 해석해서 테마 후보 도출**: 단어/기업명/인물명 빈도수 집계가 아니라, 뉴스 내용을 실제로 읽고 그 이면의 테마를 추론한다.
   예) "폭염으로 정전" 뉴스 → 테마는 "폭염"이 아니라 "스마트그리드/전력설비"
3. **테마는 반드시 섹터·현상 단위**로 잡는다. 개별 종목명 자체를 테마로 만들지 않는다 (종목은 테마 아래 딸리는 것).
4. **검증**: 도출한 테마 후보가 몇 개의 서로 다른 기사에서, 몇 개의 서로 다른 섹션(우선순위1 + 참고사항)에서 뒷받침되는지 확인한다.
5. **기준 미달이면 테마 선정 안 함**: 뉴스가 부족하면 억지로 테마를 만들지 않는다. 예전 글들도 그런 날은 메인 테마 없이 짧게 넘어갔음.

검증된 "뉴스 패턴 → 테마" 매핑은 [theme_glossary.md](theme_glossary.md)에 누적 기록한다.

## 결과물 (매일)
- `초안_YYYYMMDD.html` / `.md`: 실제 포스팅용 초안 (복붙 대상)
- `판단로그_YYYYMMDD.html`: 그날 모니터링·테마판단·종목선정 근거 정리 (검토용)
- `이미지_YYYYMMDD/`: 번호 매긴 이미지 폴더

## 판단로그의 기사 시각 표기
본문을 실제로 읽은 기사는 절대시각과 함께 "모니터링 시점 기준 -N시간 전" 형태도 같이 적는다.
나중에 다시 볼 때 시간창(전일 15:30~당일 07:30) 안에 드는 기사였는지 계산 없이 바로 판단할 수 있게 하기 위함.

## 사용자 첨삭 학습 프로세스
- 사용자가 초안을 직접 수정한 최종본을 `포스팅본안/` 폴더에 날짜별로 쌓아둔다.
- 매일 반영하지 않고 **1주일 단위**로, 그 주에 쌓인 포스팅본안과 원래 초안을 비교해서 문체·구성 차이를 학습하고 이 문서나 관련 스크립트에 반영한다.
- 즉각 반영이 필요한 수정사항은 사용자가 그때그때 직접 요청하며, 이건 주간 비교와 별개로 바로 처리한다.
